# QAPP revision notes (running list)

Purpose: every place where the pipeline had to interpret, fill a gap in, or depart from QAPP v3 (May 2023, Addendum April 2024) is recorded here, with how and why, so the next QAPP update (about every 5 years) can fix it. Rule agreed 2026-11-17: the current QAPP's intent is the guide; where we interpolate to keep the application logical, the report text describes how and why, and an entry is added here. Report text that interpolates should say so explicitly.

| Topic | QAPP v3 text | Issue | How the pipeline handles it | Suggested QAPP change |
|---|---|---|---|---|
| Completeness measures A and B | Measure 1 "collected divided by usable" goal 85%; measure 2 "planned divided by usable" goal 60% (p. 22-23) | Both ratios are inverted as worded (would exceed 100%); the QAPP's own formula is (T - (I + NC)) / T, which is usable over expected | A = Accepted results / results collected; B = Accepted results / planned results (decided 2026-11-17) | State both as usable divided by collected and usable divided by planned; say whether "usable" means Result Status Accepted; say the unit (results vs samples) and whether QC samples count |
| Completeness vs ADEC | ADEC 2026 guidance: 80-90% per analytical parameter and field measurement type | Goal 85% is inside the range; 60% secondary goal is below it; ADEC's formula (T expected) matches the QAPP's measure B numerically | Show QAPP goals as primary, ADEC range beside them | Justify the 60% goal or state which measure ADEC's 80-90% applies to |
| Completeness reporting | Report needs a completeness table per analyte (scheduled, collected and valid, goal) and per site | No planned-sample design is in the QAPP in machine-readable form | Template supplies a planned-samples design file (user to provide a generalized template) | Add a planned-sample table by site, event and analyte |
| Qualifier E | Table 7 defines E identically to DL | Probable typo | Copied as written in `reference/qualifier_definitions.csv`, with a note | Correct the definition of E |
| LOD definition | Table 7: LOD is 1/2 of the LOQ | SGS EDD data give LOD as 0.75 x LOQ | Pipeline uses EDD values; question to SGS pending | Reconcile with SGS and state the rule |
| Blank criterion | QAPP does not state a blank acceptance limit | ADEC 2026 uses a result at or above the LOQ; QAPP-silent otherwise | QAPP-style rule: any detection in a blank fails; ADEC rule shown beside it; results below 5x the blank result in the same batch are Rejected (KWF project convention, `qc: blank_multiple` in `config.yml`) | State the blank rule and the multiple |
| LLQC | Table 7 lists LLQC; no limits | No acceptance limits documented | LLQC rows are not evaluated | Give LLQC limits or drop the sample type |
| MS/MSD failures | No scope stated | Matrix failures do not indicate a batch problem | Failure rejects only the parent sample | State the scope of rejection for each QC type |
| Rejected results | No rule on public status | | Rejected results stay in the dataset with status Rejected and qualifier QCF | State how rejected data are reported to WQX |
| Field and trip blanks | | No rule for rejecting associated results | Reported and listed; do not reject other results (user decision) | State whether a failing field blank rejects the associated sample |

| Q18 | QAPP gives no tolerance for dissolved > total. Interpolated: the field duplicate RPD limit for the characteristic is the tolerance; beyond it requires a user accept/reject decision. | Added 2026-11-24 |

| Q19 | QAPP v3 Table 5 gives fecal coliform no precision (RPD) criterion. Project decision: fecal coliform duplicates are reported with the RPD but never reject. Recommend the next QAPP state a criterion. Also: QAPP is silent on a detect vs non-detect duplicate pair; the project requires a user decision. | Added 2026-11-24 |

| Planned QC samples (Q3, Q23) | Field replicates: B.5 says a minimum of 10% of samples, with 2 replicates in the spring event and again in summer; the QC table footnote says 2 replicates in the summer event. Field blanks: "sites below River Mile 30" in B.5, "at and below River Mile 30" in the QC table footnote; 2 per event. | Replicate wording conflicts (spring and summer vs summer only). Practice is 2 duplicates in every event (user, 2026-11-24), which is about 9% of 22 sites, below the stated 10% minimum. Field blank site rule conflicts ("below" vs "at and below" RM 30). | Template pre-fills 2 duplicates and 2 field blanks per event; field blanks and dissolved metals at RM 30 and downstream (smaller river-mile numbers), including RM 30. Counts are flagged for confirmation each year. | State replicates as 2 per event in spring and summer and drop or restate the 10% minimum; say "at and below RM 30" for field blanks, consistently |
| Trip blanks and BTEX | Trip blank: 1 per cooler or shipment, BTEX | QAPP does not say BTEX (and so trip blanks) is collected in summer only | No BTEX and no trip blanks in spring (user, 2026-11-24); template pre-fills this and flags it for confirmation | State that BTEX and trip blanks are summer-only |

| Completeness denominator (Q23, Q25, Q26) | T = "total number of expected measurements"; completeness compares usable data with "data called for in the sampling plan" (p. 22-23) | QAPP does not say whether planned field QC samples (duplicates, field blanks, trip blanks) count toward T | Planned field QC samples count in the denominator (user, 2026-11-24); lab-internal QC (method blanks, LCS, matrix spikes) does not; reports show primary and QC counts separately | State that planned field QC samples are included in T and lab-internal QC is excluded |
| Trip blank counting (Q23) | Trip blank: 1 per cooler or shipment | QAPP does not say how a trip blank that covers several sites is counted | One planned result per analyte per site the cooler covers, matching how the data are recorded (one record per site); the workbook lists the river miles each cooler covers (user, 2026-11-24) | State how a multi-site trip blank is counted toward expected results |
| Site coordinates (Q28) | QAPP lists coordinates for each baseline site, registered in CDX | Crews sample at a modified location at some sites (2025 fixture: 10000020, about 208 m from the registered point); new CDX locations would need a re-approved QAPP | Upload uses the registered CDX location and coordinates only (user, 2026-11-25); Q28 flags and documents any sampled-location difference (`output/q28_coordinate_differences.csv`, notes column) | Update the site coordinates to the locations actually sampled at the next QAPP revision |
